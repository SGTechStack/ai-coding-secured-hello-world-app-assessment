# Architecture

```
browser (localhost:3000)                      Spring Boot (localhost:8080)
┌──────────────────────────┐   fetch + cookie  ┌──────────────────────────────────────────────┐
│ React 19 SPA             │ ────────────────► │ CorrelationIdFilter → SessionRepositoryFilter │
│  api/client.ts (CSRF,    │ ◄──────────────── │ → Spring Security chain (CSRF, CORS, authz)   │
│  credentials, ApiError)  │  problem+json     │ → @RestController → @Service → JPA / H2        │
└──────────────────────────┘                   └──────────────────────────────────────────────┘
```

## Backend packages (`backend/src/main/java/com/example/hello`)

| Package | Contents |
| --- | --- |
| `config` | `SecurityConfig` (filter chain, CORS, CSRF, headers, `AuthenticationManager`), `SessionConfig` (Spring Session + cookie serializer), typed `@ConfigurationProperties`, `ClockConfig`, `OpenApiConfig` |
| `common` | `CorrelationIdFilter`, `AuditLogger`, `ApiExceptionHandler` (ProblemDetail), `ProblemJson`, `ApiException` hierarchy |
| `user` | `User` entity, `Role`, `UserRepository`, `PasswordPolicy`, `RegistrationService`, DTOs |
| `auth` | `LoginService`, `AppUserDetailsService`, `AccountLockoutService`, `IpLoginThrottle`, `SessionInvalidationService`, JSON 401/403 handlers, `AuthController`, `session/InMemoryIndexedSessionRepository` |
| `passwordreset` | `PasswordResetToken` entity/repository, `TokenHasher`, `EmailService` (+ logging stub), `PasswordResetService`, controller |
| `admin` | `AdminUserService`, `AdminUserController`, `AdminBootstrap` (+ properties) |
| `hello` | `HelloController` |

Rules enforced by `ArchitectureTest` (ArchUnit): controllers never touch repositories or entities; `common` never depends on a feature package.

## Request lifecycle for login

1. SPA calls `GET /api/auth/csrf` → Spring Session creates an anonymous session, `HttpSessionCsrfTokenRepository` stores a token in it, the (XOR-masked) token is returned.
2. SPA `POST /api/auth/login` with cookie + `X-CSRF-TOKEN`.
3. `CsrfFilter` validates the header. `LoginService` checks the IP throttle, then delegates to `AuthenticationManager` (`DaoAuthenticationProvider` → `AppUserDetailsService`, BCrypt).
4. On success: failure counter reset, `ChangeSessionIdAuthenticationStrategy` rotates the session id, `CsrfAuthenticationStrategy` drops the old CSRF token, `HttpSessionSecurityContextRepository` stores the `SecurityContext` in the session. Audit line `LOGIN_SUCCESS`.
5. On failure: counter incremented (lock at N), IP failure recorded, audit line, generic `401`.

## Cross-cutting security controls (PRD non-functional requirements)

| Requirement | Where |
| --- | --- |
| BCrypt only | `SecurityConfig.passwordEncoder`, used by registration, reset, bootstrap |
| HttpOnly / Secure / SameSite cookie, fixation protection, invalidation on logout & reset | `SessionConfig.cookieSerializer`, `SecurityConfig` session management + logout, `SessionInvalidationService` |
| CSRF on all state-changing endpoints | `SecurityConfig` (no `ignoringRequestMatchers`), SPA `api/client.ts` |
| CORS allow-list with credentials | `SecurityConfig.corsConfigurationSource`, `app.security.allowed-origins` |
| Enumeration resistance | `InvalidCredentialsException` (single message), `PasswordResetController.REQUEST_ACCEPTED` |
| Transport | HTTPS termination in front of the app; `server.forward-headers-strategy=native`, HSTS from Spring Security defaults on secure requests |
| Audit logging | `AuditLogger` → logger `AUDIT`; events: `USER_REGISTERED`, `LOGIN_SUCCESS`, `LOGIN_FAILURE`, `LOGIN_THROTTLED`, `ACCOUNT_LOCKED`, `PASSWORD_RESET_REQUESTED`, `PASSWORD_RESET_COMPLETED`, `USER_ENABLED/DISABLED`, `USER_ROLE_CHANGED`, `USER_DELETED`, `ADMIN_BOOTSTRAPPED`; never passwords or tokens |
| Least privilege | URL rule `/api/admin/**` → `hasRole('ADMIN')` **and** `@PreAuthorize` on `AdminUserController` |

## Scaling notes / deliberate simplifications

- Sessions and the IP throttle are in-memory and per JVM. For more than one backend instance, replace `InMemoryIndexedSessionRepository` with Spring Session JDBC/Redis (the services only depend on `FindByIndexNameSessionRepository`) and back `IpLoginThrottle` with Redis.
- H2 schema is generated by Hibernate in dev/test (`ddl-auto`). Production should ship Flyway/Liquibase migrations and keep `validate`.
- `LoggingEmailService` prints reset links to the console; wire a real `EmailService` before any real deployment.
- JWT is deliberately not implemented; see the PRD appendix and `docs/adr/0001-session-cookie-auth.md`.
