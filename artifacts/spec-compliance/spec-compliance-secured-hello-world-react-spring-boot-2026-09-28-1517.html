Must resolve before implementation begins

  • Policy: IM8 as-15: Password Change — There is no way to force an Account to change its password when compromise is suspected: the forced-change mechanism is deliberately excluded (ADR 0001). Only Admin disable and owner notifications exist. This is a security-scope decision.
  • Policy: IM8 ac-2: Multi-Factor Authentication (MFA) Enforcement — Admins log in with password only; MFA/2FA is out of scope. Privileged logins and privileged actions have no MFA or step-up. Security-boundary decision.
  • Policy: IM8 ac-3: Inactive and Expired Accounts — Inactivity disablement (scheduled hygiene jobs) is excluded (ADR 0001); no Account is ever disabled for inactivity.
  • Policy: IM8 ac-4: Access Review — The Admin list shows roles, but there is no declared per-Account permission baseline and no periodic review or revocation (role-revocation jobs excluded).
  • Policy: IM8 ac-6: Default Credentials — The Bootstrap Admin's configured credentials are never forced to change on first login (forced change excluded), and the dev fallback admin/password exists. Security-boundary decision.
  • Policy: IM8 ac-7: Singpass/Corppass for Public Users — The deployment audience (internal staff vs public users) is not declared, and the PRD mandates local username/password accounts. Public users would need Singpass/Corppass step-up for high-risk transactions; internal users would need WOG AAD.
  • Policy: IM8 ac-8: Automated Account Lifecycle Management — The deployment audience (internal staff vs public users) is not declared, and the PRD mandates local username/password accounts. Accounts come from self-registration, with no SCIM, push protocol or SSO JIT provisioning.
  • Policy: IM8 ac-12: Single Sign-On (SSO) for Internal Services — The deployment audience (internal staff vs public users) is not declared, and the PRD mandates local username/password accounts. If internal, users must authenticate through the organisational IdP, not local credentials.
  • Policy: IM8 dp-8: Data Classification Disclosure — The deployment audience (internal staff vs public users) is not declared, and the PRD mandates local username/password accounts. For an internal application, a classification label ('Confidential') must appear next to every input field; the spec has none.
  • Policy: IM8 lm-16: Key Signals Monitoring — Request logs carry duration and status, but there are no metrics for latency, traffic, errors and saturation (no Actuator/Micrometer metrics or management endpoint). Adding one is a technology and exposure decision.
  • Policy: IM8 lm-18: Whole of Government Application Analytics (WOGAA) — The deployment audience (internal staff vs public users) is not declared, and the PRD mandates local username/password accounts. A public-facing service must embed the WOGAA script (and the SPA CSP must allow it); internal-only is N/A.

Auto-fix items (clarify details or tighten wording)

  • Policy: IM8 as-2: Parameterised Interfaces — Spring Data JPA is chosen, but the spec never forbids string-built SQL/JPQL. Add: all queries use derived or parameterised queries (bound parameters only); no string concatenation into SQL, JPQL or native queries.
  • Policy: IM8 as-3: Output Sanitisation — React escapes by default, but the spec doesn't say so. Add: the SPA renders all server data as text, never via dangerouslySetInnerHTML; GET /hello returns JSON or text/plain, not HTML.
  • Policy: IM8 as-8: Secrets Management — Bootstrap Admin password, IP-hash HMAC key and datasource credentials come from 'configuration'; the README says 'environment variables or a secrets manager'. Tighten to: outside dev these MUST be injected from a secrets manager; never committed to the repo or config files, never logged.
  • Policy: IM8 as-13: Exposure of Internal System Details — The global handler returns ProblemDetail, but the spec doesn't say what a 500 contains. Add: unexpected errors return a generic detail with code internal_error, never exception messages, stack traces or SQL (server.error.include-* = never), and a test for it.
  • Policy: IM8 ac-1: Principle of Least Privilege — URL-role mapping with default deny and the /me ownership check are specified, but '@EnableMethodSecurity with a simple role check' doesn't say where annotations go. Add: @PreAuthorize("hasRole('ADMIN')") on every Account administration service method, in addition to the URL rule.
  • Policy: IM8 dp-3: Data in Transit Encryption — TLS is required outside dev as a deployment requirement, but the minimum protocol and internal connections are unstated. Add: TLS 1.2+ only (no SSLv3/TLS 1.0/1.1), database connections over TLS outside dev, never disable certificate or hostname validation. dev HTTP stays as recorded.
  • Policy: IM8 ck-2: Cryptographic Key Rotation — The IP-hash HMAC key has no rotation rule. Add: rotated periodically through the secrets manager; rotation only breaks correlation of source.ip_hash across the rotation point.
  • Policy: IM8 ck-4: Cryptographic Key Storage — The HMAC key's storage isn't stated. Add: outside dev it comes from the secrets manager with least-privilege access, is never committed, logged or exposed; the app fails at startup if it is missing outside dev.
  • Policy: IM8 st-3: Public Vulnerability Disclosure Programme — No disclosure channel. Add: the SPA serves /.well-known/security.txt (RFC 9116) with a security contact and expiry; the contact address must be supplied.
