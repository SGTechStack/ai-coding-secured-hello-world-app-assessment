High-Priority Issues

High, must fix (code-review SP-11): spring.datasource.hikari.connection-test-query runs SQL on the app's connections and is not refused.

When the property is set, Hikari stops using JDBC4 isValid() and runs the query with statement.execute(...): once at pool start (checkValidationSupport) and on every borrow of a connection idle for more than about 500 ms (isConnectionDead). H2's Parser.prepareCommand accepts ;-separated statements. So spring.datasource.hikari.connection-test-query=SET LOCK_TIMEOUT 0 (or SPRING_DATASOURCE_HIKARI_CONNECTIONTESTQUERY) passes the validator in both postures and keeps undoing the LOCK_TIMEOUT pin. Because sa is admin, CREATE ALIAS … createTcpServer; CALL … also opens a database server, which defeats ADR-072 / R-CFG-021. This is the same effect as the connection-init-sql that round 3 refused.

Fix: add spring.datasource.hikari.connection-test-query to DATASOURCE_BYPASS_PREFIXES and a case to settingsThatReachTheDatabasePastTheUrlRulesRefuseStartup. H2's driver supports isValid(), so the property is not needed. Suggested, not required: since a sibling key has turned up for the third round running, switch the Hikari rule to an allowlist (maximum-pool-size, minimum-idle, connection-timeout, idle-timeout, max-lifetime, pool-name).
