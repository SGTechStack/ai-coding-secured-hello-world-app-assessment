Must resolve before implementation begins

  • IM8 as-8 (Secrets Management): Admin bootstrap credentials are supplied via plain configuration properties (app.admin.username, app.admin.password) with no secrets-management solution named. Passwords, DB credentials, and the session/reset-token secret must be sourced from a secrets manager or environment-injected secret store, never committed to config. This is a security-boundary decision and is not auto-fixed.
  • IM8 ac-2 (MFA Enforcement): MFA/2FA is explicitly out of scope, yet the app ships privileged ADMIN accounts that can enable/disable, change roles, and delete users. IM8 requires MFA (or step-up auth) for privileged account logins and privileged actions. Waiving MFA for admins is a security-boundary decision requiring explicit sign-off.
  • IM8 ac-6 (Default Credentials): The seeded ADMIN account is created from configured credentials with no forced password change on first login. IM8 requires a mandatory password change on first login after admin-issued/temporary credentials.

Auto-fix items (clarify details or tighten wording)

  • IM8 as-3 (Output Sanitisation): React auto-escapes JSX and the API returns JSON, but the spec should state explicitly that all user-controlled output (e.g. "Hello, <username>", validation/error messages) is contextually encoded and that responses set a non-HTML content type where appropriate.
  • IM8 as-9 (Content Security Policy): No CSP is specified. Add a requirement for a minimally-permissive CSP response header (default-src 'self', no inline/unsafe-eval) on frontend responses.
  • IM8 as-11 (Session Management): Sessions are invalidated on logout and password reset, but no absolute maximum session lifetime / idle timeout is defined. Add a maximum session duration after which re-authentication is forced.
  • IM8 as-15 (Password Change on Compromise): Reset invalidates sessions, but the spec does not require forcing a password change when an account is suspected compromised (e.g. after lockout/anomaly). Add an operator-triggered forced-reset path.
  • IM8 pm-6 (System Documentation): The PRD documents the data model and endpoints but lacks a data-flow diagram and network topology. Add these to satisfy system-documentation requirements.
