High-Priority Issues (resolved)

FIXED · High · im8 ck-2 Key Rotation · backend/src/main/java/sg/securedhello/mfa/TotpSecretCipher.java:47-51, 73-81

The cipher is built with one BytesEncryptor and one keyVersion. open() decrypts every envelope with the current key. The key version is written into the envelope and the row, but there is no key ring keyed by version and no re-encryption job. After a key rotation every stored row fails GCM decryption and returns 500, which breaks the yearly incremental rotation that ADR-022 requires. Fix: add a version-keyed key ring, or explicitly record rotation as deferred in the pending ledger or handover.

Correction pass: re-check of im8 ck-2 and the changed files

These changes fix ck-2. The re-check was done by the do-work orchestrator on the changed files. It covered the reviewer re-review, which surfaced one new must-fix, and an im8-focused re-check of the key-ring change.

  • TotpSecretCipher takes a ring Map<Integer, BytesEncryptor> and the current version. It seals under the current version and opens each row with its stored key_version. An unknown version throws UnknownTotpKeyVersionException, a 500 whose message names the version only. The cipher refuses to build when the current version has no key. The constant-time prefix check and the mismatch audit are unchanged.
  • app.mfa.totp.encryption.retired-keys.<version> is optional. ApplicationKeys and SecretsConfig check each retired key for shape and distinct material, and log only its fingerprint. Startup is refused when a retired key uses the current version or repeats a retired version. TotpConfig builds the ring.
  • Re-review must-fix MF-1 (High, now FIXED): a @Min/@Max constraint on the map key made Spring print the retired key as the rejected value when a version was out of range. The keys are now bound as text and range-checked in SecretsConfig, which throws InvalidKeyMaterialException naming only the property. SecretsConfigTest checks that neither the failure chain nor the captured output for versions 256, 1000 and v1 contains the key.
  • Tests: ring cases in TotpSecretCipherTest, TotpKeyRotationTest (a row sealed under v1 opens after rotating to v2), and retired-key tests in SecretsConfigTest (48 tests). TotpSecretCipher is in PIT scope. The full mvn verify -Pmutation run is green (see the ticket verification).
  • Re-sealing rows and later dropping a retired key is the operator procedure (R-CFG-005). The README documents it.

Findings below High in the other checks are unchanged and left for triage. Examples: MfaSettingsPage complexity, the stale PROFILE_KEY cache, runtime validation of the provisioning response, and duplicated redirect logic.
