# Centralising Audit Logging with a Typed Module

## 1. Introduction

As a service grows, security events — login, logout, access denial, and sensitive-operation reads — are logged in many handlers and controllers. Without a dedicated owner, the same pattern repeats: pull the user identifier, pull the correlation ID from the MDC, build the structured log event. When the schema changes, every copy must be updated, and new handlers start by copy-pasting an existing one.

A typed audit-logger module concentrates this knowledge behind a small, stable interface. Callers state what happened (`loginSuccess`, `accessDenied`, …) rather than *how* to log it. The module owns all field extraction, schema compliance, and PII-safe identity resolution.

## 2. Prerequisites

- Spring Boot 4.0+
- An MDC-based correlation filter that populates `trace.id` for every request. See [Enriching Logs with MDC](Enriching_Logs_With_MDC.md)
- A custom `UserDetails` implementation that carries the user's stable UUID. See section 3
- Schema field values from [Log_Schema.md](../Log_Schema.md)

## 3. Carry the user UUID in the security principal

`Authentication.getName()` returns a username — PII. To log a non-PII user identifier, carry the UUID inside a custom `UserDetails` so it travels with the security context.

```java
# File: src/main/java/com/example/user/AppUserDetails.java
package com.example.user;

import org.springframework.security.core.GrantedAuthority;
import org.springframework.security.core.userdetails.UserDetails;

import java.util.Collection;
import java.util.List;
import java.util.UUID;

public class AppUserDetails implements UserDetails {

    private final UUID userId;
    private final String username;
    private final String passwordHash;
    private final Collection<GrantedAuthority> authorities;
    private final boolean enabled;

    public AppUserDetails(UUID userId, String username, String passwordHash,
                          Collection<? extends GrantedAuthority> authorities, boolean enabled) {
        this.userId = userId;
        this.username = username;
        this.passwordHash = passwordHash;
        this.authorities = List.copyOf(authorities);
        this.enabled = enabled;
    }

    public UUID getUserId() { return userId; }

    @Override public Collection<? extends GrantedAuthority> getAuthorities() { return authorities; }
    @Override public String getPassword() { return passwordHash; }
    @Override public String getUsername() { return username; }
    @Override public boolean isEnabled() { return enabled; }
}
```

Return `AppUserDetails` from `UserDetailsService.loadUserByUsername`:

```java
# File: src/main/java/com/example/user/AppUserDetailsService.java (excerpt)
@Override
public UserDetails loadUserByUsername(String username) {
    AppUser user = users.findByUsername(username)
            .orElseThrow(() -> new UsernameNotFoundException("user not found"));
    return new AppUserDetails(user.getUuid(), user.getUsername(), user.getPasswordHash(),
            authoritiesFor(user.getRole()), user.isEnabled());
}
```

The UUID comes from a `uuid` column on the users table, generated by the database at insert time using `gen_random_uuid()`. Mark the JPA column `insertable = false, updatable = false` so Hibernate skips it on INSERT and the database default runs:

```java
@Column(nullable = false, unique = true, columnDefinition = "UUID", insertable = false, updatable = false)
private UUID uuid;
```

## 4. Define the typed audit-logger interface

Create one `@Component` per bounded context that emits audit events for that context. Each method takes only what it needs; the module extracts everything else internally.

```java
# File: src/main/java/com/example/audit/AuditLogger.java
package com.example.audit;

import jakarta.servlet.http.HttpServletRequest;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.slf4j.MDC;
import org.springframework.security.core.Authentication;
import org.springframework.security.web.authentication.WebAuthenticationDetails;
import org.springframework.stereotype.Component;
import com.example.user.AppUserDetails;

import java.util.List;
import java.util.UUID;

@Component
public class AuditLogger {

    private static final Logger audit = LoggerFactory.getLogger("audit");

    public void loginSuccess(Authentication authentication) {
        audit.atInfo()
                .setMessage("Authentication succeeded.")
                .addKeyValue("event.kind", "event")
                .addKeyValue("event.category", List.of("process"))
                .addKeyValue("event.type", List.of("user"))
                .addKeyValue("event.action", "user-authentication")
                .addKeyValue("event.outcome", "success")
                .addKeyValue("event.severity", "low")
                .addKeyValue("user.id", resolveUserId(authentication))
                .addKeyValue("source.ip", resolveClientIpFromAuth(authentication))
                .addKeyValue("trace.id", MDC.get("trace.id"))
                .log();
    }

    public void loginFailure(HttpServletRequest request) {
        // Do NOT log any user identifier: the account may not exist, and logging even
        // a hashed username would confirm account existence to anyone who reads logs.
        audit.atWarn()
                .setMessage("Authentication failed.")
                .addKeyValue("event.kind", "event")
                .addKeyValue("event.category", List.of("process"))
                .addKeyValue("event.type", List.of("user"))
                .addKeyValue("event.action", "user-authentication")
                .addKeyValue("event.outcome", "failure")
                .addKeyValue("event.severity", "medium")
                .addKeyValue("error_code", 401)
                .addKeyValue("error_category", "cert/auth")
                .addKeyValue("error_follow_up_action", false)
                .addKeyValue("source.ip", request.getRemoteAddr())
                .addKeyValue("trace.id", MDC.get("trace.id"))
                .log();
    }

    public void accessDenied(Authentication authentication, HttpServletRequest request) {
        var builder = audit.atWarn()
                .setMessage("Authorisation denied.")
                .addKeyValue("event.kind", "event")
                .addKeyValue("event.category", List.of("process"))
                .addKeyValue("event.type", List.of("denied"))
                .addKeyValue("event.action", "access-control")
                .addKeyValue("event.outcome", "failure")
                .addKeyValue("event.severity", "medium")
                .addKeyValue("error_code", 403)
                .addKeyValue("error_category", "cert/auth")
                .addKeyValue("error_follow_up_action", false)
                .addKeyValue("http.request.method", request.getMethod())
                .addKeyValue("url.path", request.getRequestURI())
                .addKeyValue("source.ip", request.getRemoteAddr())
                .addKeyValue("trace.id", MDC.get("trace.id"));
        UUID userId = resolveUserId(authentication);
        if (userId != null) {
            builder = builder.addKeyValue("user.id", userId);
        }
        builder.log();
    }

    public void logout(Authentication authentication, HttpServletRequest request) {
        var builder = audit.atInfo()
                .setMessage("User logged out.")
                .addKeyValue("event.kind", "event")
                .addKeyValue("event.category", List.of("process"))
                .addKeyValue("event.type", List.of("end"))
                .addKeyValue("event.action", "user-logout")
                .addKeyValue("event.outcome", "success")
                .addKeyValue("event.severity", "low")
                .addKeyValue("source.ip", request.getRemoteAddr())
                .addKeyValue("trace.id", MDC.get("trace.id"));
        UUID userId = resolveUserId(authentication);
        if (userId != null) {
            builder = builder.addKeyValue("user.id", userId);
        }
        builder.log();
    }

    public void profileRead(UUID userId, HttpServletRequest request) {
        audit.atInfo()
                .setMessage("Profile read.")
                .addKeyValue("event.kind", "event")
                .addKeyValue("event.category", List.of("process"))
                .addKeyValue("event.type", List.of("allowed"))
                .addKeyValue("event.action", "profile-read")
                .addKeyValue("event.outcome", "success")
                .addKeyValue("event.severity", "low")
                .addKeyValue("user.id", userId)
                .addKeyValue("http.request.method", request.getMethod())
                .addKeyValue("url.path", request.getRequestURI())
                .addKeyValue("source.ip", request.getRemoteAddr())
                .addKeyValue("trace.id", MDC.get("trace.id"))
                .log();
    }

    private static UUID resolveUserId(Authentication auth) {
        if (auth != null && auth.getPrincipal() instanceof AppUserDetails user) {
            return user.getUserId();
        }
        return null;
    }

    private static String resolveClientIpFromAuth(Authentication auth) {
        if (auth != null && auth.getDetails() instanceof WebAuthenticationDetails details) {
            return details.getRemoteAddress();
        }
        return null;
    }
}
```

## 5. Use the module in handlers and controllers

Inject `AuditLogger` as a Spring bean. Handlers become thin: they call one audit method and write the HTTP response.

```java
# File: src/main/java/com/example/auth/AuthenticationSuccessAuditHandler.java (excerpt)
@Component
public class AuthenticationSuccessAuditHandler implements AuthenticationSuccessHandler {

    private final AuditLogger auditLogger;
    private final ObjectMapper objectMapper;

    public AuthenticationSuccessAuditHandler(AuditLogger auditLogger, ObjectMapper objectMapper) {
        this.auditLogger = auditLogger;
        this.objectMapper = objectMapper;
    }

    @Override
    public void onAuthenticationSuccess(HttpServletRequest request, HttpServletResponse response,
                                        Authentication authentication) throws IOException {
        auditLogger.loginSuccess(authentication);
        // HTTP response writing stays here — it is a separate concern from audit logging
        response.setStatus(HttpServletResponse.SC_OK);
        response.setContentType(MediaType.APPLICATION_JSON_VALUE);
        objectMapper.writeValue(response.getWriter(), new CurrentUserResponse(...));
    }
}
```

```java
# File: src/main/java/com/example/auth/AuthenticationFailureAuditHandler.java (excerpt)
@Override
public void onAuthenticationFailure(HttpServletRequest request, HttpServletResponse response,
                                    AuthenticationException exception) throws IOException {
    auditLogger.loginFailure(request);
    response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
    response.setContentType(MediaType.APPLICATION_JSON_VALUE);
    objectMapper.writeValue(response.getWriter(), GENERIC_401);
}
```

## 6. Test with Logback ListAppender

Because `AuditLogger` is a plain Spring component with no mandatory application context, unit tests can instantiate it directly and capture output with a `ListAppender`.

```java
# File: src/test/java/com/example/audit/AuditLoggerTest.java
class AuditLoggerTest {

    private AuditLogger auditLogger;
    private ListAppender<ILoggingEvent> appender;
    private final UUID userId = UUID.fromString("00000000-0000-0000-0000-000000000001");

    @BeforeEach
    void setUp() {
        auditLogger = new AuditLogger();
        appender = new ListAppender<>();
        appender.start();
        Logger logger = (Logger) LoggerFactory.getLogger("audit");
        logger.addAppender(appender);
        logger.setLevel(Level.ALL);
        MDC.put("trace.id", "test-trace-123");
    }

    @AfterEach
    void tearDown() {
        ((Logger) LoggerFactory.getLogger("audit")).detachAppender(appender);
        MDC.clear();
    }

    @Test
    void loginSuccess_emitsInfoEvent_withUserIdAndSourceIp() {
        Authentication auth = authWithDetails(userId, "alice", "192.168.1.1");

        auditLogger.loginSuccess(auth);

        ILoggingEvent event = appender.list.get(0);
        Map<String, Object> kv = kvMap(event);
        assertThat(event.getLevel()).isEqualTo(Level.INFO);
        assertThat(kv).containsEntry("event.action", "user-authentication")
                      .containsEntry("event.outcome", "success")
                      .containsEntry("user.id", userId)
                      .containsEntry("source.ip", "192.168.1.1")
                      .containsEntry("trace.id", "test-trace-123");
        assertThat(kv).doesNotContainKey("user.hash"); // never log hashed PII
    }

    @Test
    void loginFailure_emitsWarnEvent_withNoUserIdentity() {
        MockHttpServletRequest request = new MockHttpServletRequest("POST", "/login");
        request.setRemoteAddr("10.0.0.1");

        auditLogger.loginFailure(request);

        Map<String, Object> kv = kvMap(appender.list.get(0));
        assertThat(kv).doesNotContainKey("user.id")
                      .doesNotContainKey("user.hash"); // account may not exist
    }

    private static Map<String, Object> kvMap(ILoggingEvent event) {
        return event.getKeyValuePairs().stream()
                .collect(Collectors.toMap(p -> p.key, p -> p.value));
    }
}
```

## 7. Key decisions

- **One method per event type**: typed methods make each call site self-documenting and prevent schema drift when a new event type is added.
- **No user identity on authentication failures**: the account may not exist; logging even a hashed username confirms its existence. Use `trace.id` for correlation instead.
- **UUID, not username**: `user.id` is a non-PII stable identifier. Never log raw usernames, emails, or hashed usernames.
- **`source.ip` on every security event**: use `WebAuthenticationDetails.getRemoteAddress()` for events triggered by Spring Security (where `Authentication.getDetails()` carries it), and `request.getRemoteAddr()` elsewhere.
- **`error_code`, `error_category`, `error_follow_up_action` on failures**: use underscore separators, not dot-notation, because the ECS formatter pre-seals the `error.*` nested object. See [Log_Schema.md](../Log_Schema.md).
- **Audit logger owns no HTTP concerns**: HTTP status code, response body, and headers remain the caller's responsibility. The separation keeps `AuditLogger` testable without a running servlet container.

## 8. Conclusion

A typed audit-logger module turns a scattered, copy-paste pattern into a single owner. Adding a new event type means adding one method; changing the schema means editing one class; testing means asserting on a `ListAppender` — no integration test required for the schema.

### Key Takeaways

- **Inject `AuditLogger` as a Spring bean**: one instance per bounded context, injected wherever audit events are emitted
- **Typed methods over generic event objects**: method names document intent; the module owns field extraction
- **UUID in `UserDetails`**: carry the UUID through the security context so handlers never need a database lookup
- **No user identity on failures**: omit `user.id` when the account may not exist; the `trace.id` is sufficient for post-incident correlation
- **Test with `ListAppender`**: attach a Logback list appender to the `"audit"` logger in `@BeforeEach`; assert on key-value pairs from `ILoggingEvent.getKeyValuePairs()`
