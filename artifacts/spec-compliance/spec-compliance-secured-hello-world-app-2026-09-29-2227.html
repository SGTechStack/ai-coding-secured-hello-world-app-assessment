Scope of this run

Second audit of the same subject. The first run (2026-09-29-2157) audited the PRD alone, before issue decomposition. This run audits the PRD plus .scratch/secured-hello-world/spec.md and all 27 tickets produced by decomposition, so the question is no longer “does the PRD mandate this control” but “does a ticket now mandate it in specific, testable form”.

A PASS here means the spec mandates the control. It does not mean code implements it — no code exists yet. The im8-review skill performs the code-level audit later under a stricter evidence standard, where a control delegated to a framework counts as WARN rather than PASS unless the module is both imported and configured in the application’s own code. Some verdicts below are expected to downgrade at that gate.

PRD out-of-scope items → waiver disposition

The specific question put to this run. The PRD lists six exclusions; the waiver register carried four. Every exclusion now has a traceable control disposition with residual risk and compensating controls. A waiver is a decision to accept a gap; N/A is a finding that the control has nothing to attach to. Conflating them is how a compliance document flatters itself.

Caveats on this audit

  • Control-family names are descriptive and have not been verified against IM8 source text. No clause identifiers are cited. Pinning real control IDs requires the agency control matrix.
  • Risk classification is Low Risk, chosen because LR is the higher of the two levels wherever the catalogue’s LR and MR differ — so the choice cannot under-call a severity.
  • A spec-phase PASS means the spec mandates the control. Treating one as implementation evidence is the single most misleading thing this report could be used for.
  • Re-verify against the im8-review code-level audit before sign-off. That is the gate; these verdicts are not the final word.
