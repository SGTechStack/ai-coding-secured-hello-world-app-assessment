# Test plan: which test proves which control

This is the canonical test table for the Secured Hello World auth app. Each row names one control, the assertion
that proves it, and the clause or decision it answers to. The rows cover the design decisions and the test sections
of the governing standards and the PRD. The table below is the only thing in this file that parses as rows. The
traceability gate (ADR-068) reads this file through the Maven property `test-plan.path`.

Rules:

- Every automated test cites its row with `@Proves("T-…")`. Vitest and Playwright tests put the ID in the test name.
  `verify` fails when a row has no test, when a test cites an unknown ID, when this file is missing or unreadable
  (T-BLD-007), or when it parses zero rows or its header differs from the fixed column list (T-BLD-008). The gate
  proves that a test exists. It does not prove what the test asserts.
- The columns are fixed. Adding, removing or reordering one amends T-BLD-008 and the gate's parser in the same change.
- One ID may cover a parameterised or matrix-generated test.
- IDs are never renumbered or reused. A deleted row retires its ID.
- Amend this table by ID. Nothing else holds a copy of these rows.
- Every row has exactly one pillar, chosen by the control it proves.

Legend:

- **Level:**
  - U: unit
  - C: full context, MockMvc
  - P: full context on a real port
  - R: runner process
  - B: build artefact
  - A: ArchUnit
  - F: Vitest
  - E: Playwright (Chromium and Firefox)
- **Context:** `ctx-default`, `ctx-port`, `ctx-locktimeout` and `ctx-nondev` are the fixed Spring test contexts
  (ADR-065, ADR-067). `restart` is the harness that runs outside the context cache, as one or two sequential
  `SpringApplicationBuilder` runs on one file path. `runner` is the rebinding runner process. For levels that start
  no Spring context, the column reads `none` (U), `archunit`, `build`, `vitest` or `playwright`.
- **Isolation:**
  - `keyed`: fresh fixture usernames and source keys.
  - `delta`: asserts a before/after delta on a global count.
  - `own-DB`: runs against its own database.
  - `merged`: the one ordered test on the shared `unparseable` bucket.
  - `none`: no shared mutable state.
- **Clause:** the requirement or decision the row proves, as primary clauses first and then surviving IDs.
  - ASVS IDs are OWASP ASVS 5.0 and always carry their level. An L2 or L3 citation is a per-control claim.
  - `Std §N:line` is section N, line `line` of the Standalone User Access Control Application Standard.
  - `MFA §N:line` is the MFA_Core standard (`Base_Standalone_Application_Standard.md`), and `MFA Recipe n:line` its
    reimplementation recipes (`Base_Standalone_Reimplementation_Recipes.md`).
  - `FE-STD §N:line` is the MFA Frontend Standalone standard. `LOG §N:line` is the Structured Logging Application
    Standard.
  - `PRD Story n`, `PRD §Section` and `PRD Lnnn` (line) point into the product requirements document.
  - `IM8 xx-n` is an IM8 control. RFC, CWE, NIST and CVE IDs are cited as published.
  - `TM-nn` is a threat in [`../threat-model/report.md`](../threat-model/report.md). `ADR-nnn` and `REJ-nnn` are in
    [`../adr/README.md`](../adr/README.md). `R-…` rows are in [`../register/register.md`](../register/register.md).
- **Rationale:** one standalone sentence, with its primary citation, on a row whose invariant looks wrong but is not:
  a maintainer would plausibly undo it, and this test is what fails when they do. Empty on every other row.
- **Polarity:** `neg` asserts a refusal, an absence or a fail-closed outcome. `pos` asserts an expected success.
