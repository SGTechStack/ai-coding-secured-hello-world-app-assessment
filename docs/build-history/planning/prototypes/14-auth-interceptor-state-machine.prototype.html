Throwaway prototype — not the build

What the app believes, and what it does when the server disagrees

The session cookie is HttpOnly, so this app can never look at it. It only ever learns where it stands by asking the server and reading the reply. This page lets you drive that conversation by hand.

Press the buttons on the left and watch the panel on the right. Every exchange with the server is written into the log at the bottom, so you can count the round trips, the audit-log entries and the throwaway sessions each choice costs. The four switches are the four decisions this prototype exists to settle: each is set the way we currently intend to build it, and each can be flipped to the obvious-but-wrong alternative so you can feel what goes wrong.

The question: is this the right set of rules for discovering who you are, keeping the form-submission token fresh, and recovering when the server asks for a second factor half-way through an action? Prototype code is thrown away; only the decisions survive.
